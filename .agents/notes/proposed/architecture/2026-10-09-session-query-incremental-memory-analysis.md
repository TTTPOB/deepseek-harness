# Agent Note: Reuse session-query caches and maintain incremental in-memory analysis

Status: proposed

English | [中文](2026-10-09-session-query-incremental-memory-analysis.zh.md)

## Problem

This proposal belongs to `deepseek-harness`'s `session-query`. Source inspection has identified the incremental integration points, reuse limits, and consistency design. The design is not implemented; behavior and performance still require implementation tests.

`readSurface` returns original events in the current message surface, ordered by their folded positions; `traceEvent` returns a single target's complete direct sources, derived references, and replacement chain. Both currently use the [corpus read path](<../../../../packages/session-query/session-query/src/index.ts#L404-L440>): obtain complete events, deeply clone payloads, and fold them again. [Shared analysis](<../../../../packages/session-query/session-query/src/tracing.ts#L181-L219>) builds N records for the entire log, although surface needs only current nodes and single-target trace needs only one record. Trace also scans later events for reverse source references.

Existing mechanisms can be reused:

| Mechanism | Existing capabilities and limits |
|---|---|
| [Session snapshot](<../../../../packages/core/session/src/index.ts#L625-L657>) | Events are deeply frozen and range reads can reference them; internal analysis need not clone complete payloads. |
| [Session SurfaceManager](<../../../../packages/core/session/src/surface.ts#L618-L701>) | It already folds current nodes incrementally as events arrive, but does not retain complete replacement history. |
| [query observation/cache](<../../../../packages/session-query/session-query/src/observation.ts#L64-L170>) | Live reads use a fixed cut; cold reads reuse restored Sessions by persistence identity/revision, while leases retain old cuts. Public observations do not directly expose surface/history. |
| [JSONL parsed cache](<../../../../packages/session/session-persistence-jsonl/src/index.ts#L760-L847>) | An unchanged revision can avoid physical I/O, decoding, and stored validation; this is not a local disk read. |

Queries therefore do not necessarily reread disk on every call, and existing Raw/page cache optimizations need not be rebuilt. A first cold miss still performs a [complete read with interrupted closers](<../../../../packages/session-query/session-query/src/cold-read.ts#L31-L56>) and Session preparation/validation. `projectionMode: "none"` skips only registry projection, not restoration.

## Proposal

This proposal refines query-internal analysis under the [existing observation ownership decision](<../../implemented/architecture/2026-08-25-session-observations-and-projection-owned-client-state.md>) and retains the observation, surface, and trace entry points in the [convenience API trimming proposal](<../simplification/2026-09-19-trim-session-query-convenience-api.md>). Neither existing record is superseded; archived records remain frozen.

### 1. Reuse observations and copy only final output

Make `readSurface` / `traceEvent` reuse existing observations and the prepared cache, analyze frozen event references within one lease/cut, and release in finally. Surface copies only the final returned current original events and header; trace owns only final metadata and seq sets. Analysis does not deeply clone complete payloads.

Generate analysis products according to the result required: surface does not generate N records; single-target trace generates only the target record; consumers that actually need the whole list still generate complete records. Preserve public return contracts, permissions, cancellation, and error categories. A local window must not stand in for a complete trace.

### 2. Build once, then maintain new logical events incrementally

For each retained session, build the necessary analysis state once, then process only new logical events when the same live Session appends normally, rather than merely caching results for a stationary cut. Cold prepared entries reuse analysis under the same persistence identity/revision. A changed revision or restoration into a new live object requires complete restoration and rebuilding; subsequent appends on that live object then maintain analysis incrementally.

Reuse the core canonical fold transformation engine to maintain replacement history, actual shadow relationships, and reverse `sourceEventSeqs` references incrementally inside query. The Session's current surface alone is not a complete analysis result. Maintain actual replacement relationships separately from source references: a source can reference diagnostics without identifying a shadowed node, and physical frame changes are not logical event changes. Appending ordinary source events also changes trace; replacement generation alone is insufficient.

These are query-internal analysis capabilities. They add no public relationship API or second persistent activity tree and do not change SQLite on-disk schema. List/Detail continue to use the bounded original-field reads in [ADR 0002](<../../../../../dsh-session-tools/docs/adr/0002-local-reading-and-completeness.md>), without requesting a complete surface/trace for each page or search hit.

### 3. Evict analysis state with its owning session cache

Attach new in-memory analysis to the existing session/restoration entry lifecycle so it is evicted, disposed, and invalidated with its cache; live state is released with the Session lifecycle. Do not create an independent unbounded cache or retain complete payloads through seq maps or closures after eviction. Existing lease rules for retaining old cuts remain valid.

Integration choices from source inspection, to confirm during implementation:

1. **Integration: process increments lazily by observation cut.** Process `[0, cut)` initially, then only `[processed, cut)`; unqueried appends add no analysis work. [Append](<../../../../packages/core/session/src/index.ts#L751-L765>) validates candidates and collects listeners, pushes events, then synchronously calls post-commit observers. Observer failures are isolated; seeds and unattached Sessions publish no events. Listening to `session/event` would still require initial replay, gap recovery, and cut control, so analysis correctness does not depend on that listener and no new bus is added.
2. **Surface: reuse the canonical transformation engine, not the Session's current result directly.** [Complete fold](<../../../../packages/core/session/src/surface.ts#L556-L615>) and [SurfaceManager](<../../../../packages/core/session/src/surface.ts#L618-L718>) share plan/apply; equivalence requires the same event prefix, interpreter behavior, and effective definitions. Query uses the [catalog](<../../../../packages/session/session-format-catalog/src/message-projections.ts>) image-offload definition, while Session uses [borrowed definitions registered in the store](<../../../../packages/core/session/src/index.ts#L928-L949>); matching names do not establish equivalence for arbitrary profiles. Public `session.surface.nodes` returns a mutable internal array for the latest cut only. Neither public nor internal state retains complete replacement history, and generation does not cover ordinary source appends. Existing [fold state](<../../../../packages/core/session/src/surface.ts#L260-L285>) and plan/apply are private. The minimal choice is to extract a resumable canonical fold accumulator from core surface for use by the original fold and query, returning the shadowedSeqs of actual replacements on each increment. Do not duplicate positional/validation algorithms or extend the Session public relationship API. This affects core session surface exports, implementation, and tests, plus session-query internal analysis; preserve the original fold callers' interface and run regressions.
3. **Cut: capture, advance, and snapshot results in one synchronous segment.** [Live observation](<../../../../packages/session-query/session-query/src/observation.ts#L285-L329>) bounds event ranges but does not freeze separate mutable relationship state. Add an internal synchronous projector for both query entry points: after asynchronous source resolution, the observation owner captures the cut, advances to it, produces the required seq/metadata or final output without an intervening await, then releases the lease. Later appends do not alter generated answers; no full relationship map or huge payload copy is needed for each call. Consuming an old lease across await requires cut-specific metadata/version. If shared state has advanced beyond the old cut, rebuild temporarily from the old lease prefix; filtering new seqs alone cannot produce the old surface. This design introduces no long-lived multiversion cache.
4. **Cold: reuse a stationary revision; rebuild first after revision changes or restoration into a new live object.** A [prepared entry](<../../../../packages/session-query/session-query/src/observation.ts#L118-L170>) hits by persistence identity/revision; otherwise a complete read/prepare creates a new entry. There is no trusted credential for resuming a logical prefix. An initial [cold read](<../../../../packages/session-query/session-query/src/cold-read.ts#L31-L56>) appends synthetic interrupted closers, potentially including a [tool/result](<../../../../packages/core/session/src/repair.ts#L118-L163>) that enters the surface and references tool/call. Later real events occupy those seqs, so the old balanced log need not be a prefix of the new log. Session construction can also append an [end-seed marker](<../../../../packages/core/session/src/index.ts#L590-L622>), while the prepared observation cut is entry.events; reading the prepared Session's latest nodes directly is invalid. Only later appends on the same live Session object are known to be resumable. Build once for a newly restored object, then increment. Do not implement cross-revision prefix comparison, synthetic-tail rollback, or cold→live state transfer.
5. **Ownership: attach cold state to PreparedEntry and live state to a reader-owned WeakMap<Session, state>.** [Eviction and leases](<../../../../packages/session-query/session-query/src/observation.ts#L227-L283>) already retain old revisions through old leases; after release without a cache reference, they can be collected. Analysis fields belong to the entry, with no separate strong-reference map keyed by id. Live analysis does not modify the Session class. Delete the corresponding weak key on session/disposed; old lease snapshots remain valid. The existing reader has no explicit clear/dispose. Add reader teardown through the [engine effect](<../../../../packages/session-query/session-query/src/index.ts#L153-L157>): clear the cache, replace the weak map, and prevent old resolving requests from refilling after dispose. State stores no second payload copy; frozen references/projected messages required for validation share their owner's lifetime.
6. **Semantics and errors: use a dedicated internal adapter, not a mechanical replacement of corpus.load.** In [trace](<../../../../packages/session-query/session-query/src/tracing.ts#L71-L110>), source contains the target's direct references, derived contains later events that directly reference the target, and replacementChain follows actual shadow replacements only. Maintain a reverse source index and replacement map separately, preserving original source order and ascending derived order. Surface returns original events in fold-node position order, retains empty-message nodes, and does not return image-offloaded Messages. [Canonical fold errors](<../../../../packages/session-query/session-query/src/tracing.ts#L181-L219>) are INVALID_SURFACE; [observation preparation](<../../../../packages/session-query/session-query/src/observation.ts#L130-L148>) uses store definitions and maps failures to CORRUPT_SESSION. Query-internal preparation uses the canonical catalog and existing Session.fromRestore validation. Distinguish it from public observation's store-definition preparation through entry modes and reuse only within the same mode; public observeSession behavior remains unchanged. On the read prefix, trace checks that the target exists before canonical fold/preparation. The adapter must distinguish original canonical surface failures from persistence corruption during new restoration validation, rather than uniformly mapping every preparation exception. Canonical fold failures remain INVALID_SURFACE. Adapt persistence corruption, source conflict, not-found, and cancellation using the existing [corpus categories](<../../../../packages/session-query/session-query/src/corpus.ts#L306-L344>); new preparation must not preemptively change error categories or skip restoration validation.

**Implementation tests are required to establish:** accumulator equivalence to complete fold after every append (replacement of replacements, extra diagnostic sources, ordinary source appends, image offload, empty messages); isolation of old cuts from new appends after asynchronous source resolution; cold synthetic tails/new-live rebuilds and old leases; original categories/check ordering for missing/unloaded interpreters, target-not-found, invalid surface, persistence errors, and cancellation; eviction, dispose/HMR, and preventing in-flight requests from refilling. These are integration points and design choices identified in source. The acceptance tests are not implemented or executed, and CPU/allocation benefits have not been measured.

## Responsibilities and impact

| Module | Design responsibility |
|---|---|
| `dsh-session-tools` | Stage 1: shared Compact/Detail associations, bounded supplementary reads, budgets, Raw, surfaces parameters, and lightweight read_seq; see [ADR 0001](<../../../../../dsh-session-tools/docs/adr/0001-shared-event-association-and-projection.md>), [ADR 0002](<../../../../../dsh-session-tools/docs/adr/0002-local-reading-and-completeness.md>), and [ADR 0003](<../../../../../dsh-session-tools/docs/adr/0003-search-and-projection-separation.md>). Consume public query only; do not open session files. |
| `session-query` | Stage 2: observation reuse for readSurface/traceEvent, on-demand results, incremental in-memory analysis, and cache lifecycle. Internal integration uses the observation owner's synchronous projector, entry/weak-key state, and error adaptation. |
| core Session / SurfaceManager | Extract an incremental accumulator extension point from the existing canonical fold, preserve Session public surface/relationship interfaces, and do not duplicate restoration. |
| SQLite / persistence / codecs | Retain index, disk format, restoration, and validation responsibilities; they are not a persistent relationship database for incremental in-memory analysis. |
| Built-in query consumers, deliverable tools, controller/GUI history, subagent | No API/schema changes are presumed. Raw/page already consume public query; full-history consumers such as controllers are not local reads and must retain complete preparation semantics. |

Existing SQLite builds documents only for events with extracted text and lacks complete source/shadow relationships and surface position order; see [document construction](<../../../../packages/session-query/session-query/src/documents.ts#L36-L74>). It serves existing search and surfaces filters, not complete surface/trace. Reusing in-memory analysis does not require a second relationship cache shared across query, SQLite, and persistence.

## Alternatives considered

**Persistent relationship tables or SQLite schema extensions: excluded.** Search documents are incomplete; completing relationships adds maintenance, migration, and invalidation costs. Reusing already-restored in-memory state is more direct.

**Disk sidecars, in-memory frame indexes, migration framing, and manual or automatic reframing: excluded from this scope.** Existing reads restore all events, and seq directly indexes memory. There is no local-disk-read consumer; a physical index alone cannot eliminate query's first complete restoration. Ordinary zstd appends use independent batch frames, while a migration body can be a single large frame, but reframing has no direct benefit in the current in-memory path. Actual local disk reads also involve JSONL open/read, codecs, and global validation responsibilities; they are not justified as an additional stage of this query optimization.

**Cross-process validation credentials or skipping global validation: excluded.** Physical location information cannot establish that the entire log and its interpreters passed current restoration validation; cross-owner version/invalidation protocols add unnecessary cost.

**Model compaction tools: a later independent decision.** Improve query and reading first; this design does not change model context or submit compaction transactions.

Evidence for physical range-read scope comes from [array slicing in JSONL read](<../../../../packages/session/session-persistence-jsonl/src/storage.ts#L158-L178>) and [streaming migration writes](<../../../../packages/session/session-persistence-jsonl/src/generation.ts#L672-L765>). These investigations support scope choices only; they do not establish a verified new reader/reframing design.

## Acceptance criteria

Stage 0 synchronizes this proposal and the consumer ADRs; stage 1 implements `dsh-session-tools` projection/search; stage 2 implements `session-query` incremental in-memory analysis. The user has authorized implementation of this proposal and the three consumer ADRs; this baseline commit changes documentation only. Keep the note in proposed until implementation acceptance. There is no storage migration, framing, or sidecar stage.

Compare pre- and post-optimization surface order, empty messages, image offload, replacement chains, direct derived/source sets, and error categories. Verify initial builds, every append, old-cut leases, and eviction/release. Measure live/cold CPU, allocations, and final-output copying, not just repeated requests against stationary logs. First-cold complete read/validation/restoration costs remain; no arbitrary first-single-event speedup is promised, and no current millisecond or memory benefit has been measured.

Decided defaults: omitting surfaces searches all existing indexed documents in current, shadowed, and log-only, as recorded in [ADR 0003](<../../../../../dsh-session-tools/docs/adr/0003-search-and-projection-separation.md>). After ADR 0001 and ADR 0002 functionality is implemented, select representative recall tasks from real session history on this machine and estimate and calibrate supplementary-read and display budgets; do not invent numeric limits beforehand. After each stage passes acceptance, remove its pending-confirmation labels and record verified values and calibration evidence in the body. Stage 2 integration and consistency choices are documented above; differential, lifecycle, and error-semantics tests remain to be implemented.

## Risks

First-cold queries still pay for complete reading, validation, and restoration; incremental benefits depend on continuous appends to the same live Session object. Interpreter-definition differences, synthetic tails, old-cut leases, and requests during dispose affect results and error semantics and require the differential and lifecycle tests above. Representative-task budgets and performance gains have not been measured; this proposal is not a verified performance guarantee.
