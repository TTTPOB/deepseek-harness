# Agent Note: PTC 原始文本词法识别与准确解析位置

Status: implemented

[English](2026-10-31-ptc-raw-token-recognition.md) | 中文

## 问题

[原始文本决策](../feature/2026-10-30-ptc-raw-text-and-parse-locations.zh.md)为嵌入文本移除一层转义。其外层优先识别也会转换合法普通字符串中的开头序列，静默改变字符串值。这影响编写原始字面量相关源码、测试或文档的程序。仅支持 JavaScript 的诊断解析器可能先停在合法 TypeScript 标注处，而非真正错误处；附加两个解析器的消息增加长度，却不便于修复。

## 决策

Acorn 及 `@sveltejs/acorn-typescript` 解析模型编写的原始源码。最外层原始插件在 `getTokenFromCode` 中拦截 @ 紧跟至少两个反引号的序列，读取到下一个最长且长度准确匹配的连续段，记录区间并发出字符串 token。其他 @ 委托给 TypeScript 插件，以保留装饰器支持。普通字符串、注释、正则及模板正文不属于原始 token；模板插值表达式可以包含原始 token。多行原始 token 之后更新 tokenizer 行状态，使后续诊断使用原始坐标。

两种格式均使用最新 ECMAScript、非严格脚本解析、位置记录，并显式允许顶层 await、return 及 import。补充解析器接受两种格式的并集；是否允许顶层 return 或 import，仍由所选 Node 类型擦除路径决定。非严格模式避免将旧式八进制变成仅 Acorn 严格模式的错误；现有类型擦除拒绝仍只返回消息。仅记录到的原始区间采用原来的保行转换变成模板；其他源码字节保持完全相同。

未闭合的原始 token 在开头位置失败。Acorn 的其他失败会回退到原来的外层优先预处理，再擦除类型。Acorn 只作补充，不成为新的接纳依据：解析器兼容缺口不能阻止现有类型擦除器接受的代码。该回退有意为 Acorn 拒绝的程序保留旧识别风险。

类型擦除失败且 Acorn 有位置时，返回 `SyntaxError at L:C: <strip message>`、原始源码行与插入符。两种格式的坐标均从 1 开始，不附加 Acorn 自身的消息。未闭合原始 token 使用相同源码帧，消息为 `Unterminated raw string literal; close it with exactly N backticks.`。Acorn 接受后类型擦除失败时，只返回类型擦除消息。不添加近似标签、生成的文件名、重复解析文本或编写建议。调用方仍返回 `kind: 'exception'`。诊断绝不执行模型代码。

## 考虑过的替代方案

**保留全局开头序列保留规则。** 它让识别简单，却静默破坏普通字符串。要求每个编写源码的程序编码 @，只是把该缺陷转嫁给调用方。

**手写字符串／注释扫描或正则与除号启发式。** JavaScript 词法上下文涉及模板、插值及 TypeScript 语法。由 Acorn 负责这些规则，而不是新增不完整的词法器。

**拒绝所有 Acorn 失败。** 补充依赖的语法缺口会让原本接受的程序退化。回退保留既有接纳路径。

**保留仅 JavaScript 的诊断编译。** 它无法跳过合法 TypeScript 标注，列号也针对转换后的源码而非原始源码。

## 后果

原始语法和模板转换仍由原功能记录维护；本记录只部分取代识别和诊断决策。本包将两个解析器声明为运行时依赖。tsdown 将其外部化，因此隔离的打包消费方必须安装并解析这些依赖；只有源码测试不足以验证该产物。

包测试覆盖普通 token 保留、正则／除号、模板插值、TypeScript 语法及装饰器、准确分隔符连续段、CRLF／LF 保留、回退，以及两种格式下的所有诊断形式。真实子进程测试和 core tarball smoke 固定原始执行、普通字符串不变及源码帧格式。原记录的组合 transcript（文本记录）覆盖缺口仍然存在；不提交私有程序语料或精确的私有统计。
